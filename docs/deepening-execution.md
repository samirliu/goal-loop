## 最终实现

### 1. 用当前地图推进，而不是重读手册

`goal_host.py enter PROJECT SECONDS` 只识别已落盘的唯一真实 prompt/会话，重复进入沿用最早截止；歧义拒绝。
宿主没有自动hook时继续用已有显式 begin，不假造SDK身份。

`goal_ctl.sh context --project PROJECT` 从原账本派生契约、head、产物指纹、接口、单元和策略状态，给出当前阶段、最早截止及准确命令。
动作携带 revision，执行前在原目录锁内重算并核对，然后 exec 原控制器。默认批准不带 `--auto`；已有授权时显式使用它，授权位也进入revision。
这不是第二套账本或完成判定。到期地图不授权派工，投影损坏及待恢复提交拒绝；已经收账并声明退出的波次转向终验，不回到实施。

真实试验暴露 hook/enter 已创建状态但尚无 goal.md 的入口。修复后提供最小契约模板、准确路径和“已初始化”提示，不自行写契约或批准；模型写完并冒烟后重新取地图。
`goal_context.py receipt PROJECT` 在同一最早截止内执行原 audit/Gate，输出原检查结果、实际策略版本、复用来源及未解决项。它不替代收账，tokens/money缺失保持null。

### 2. 只修失败或失效单元

图v1保持兼容；v2顶层结构不变，仅给job增加 `inputs`。显式依赖必须消费前驱的具体产物，v2重叠写域必须合并；v1仍保留原有保守顺序共享写支持。

单元证据绑定实际输入及其传递依赖、输出字节/模式、接口、契约/检查器/仪器和路由版本。
后续 begin 复用未失效的已验收单元，记录来源wave/unit，拒绝再次 dispatch/prepare；不伪造worker启动或首次有效时间。
前驱采用后改变会阻止后继，校验与采用之间改变接口也会拒绝。

失败简报保留检查原输出、错误、允许文件域和尝试历史。同一契约与文件域累计失败，换task名或策略标签不能清零；三次失败停止该单元。
不变条件下重试必须给出不同的断点修订说明。说明文本本身不能证明修复有效，实际检查和最终集成Gate继续决定结果。

### 3. 学习实际改变下一次派工

plan/begin 的 `--policy-state PROJECT/.goal/proposals/DIR` 运行已有合格归档，消费严格的
`{match, choice: baseline|serial, reason}` 结果，保留选中版本、匹配输入哈希、决定与运行记录。
串行规则实际把begin限制为inline，第二个并发dispatch由生产入口拒绝；prepare的worker_prefix包含相关输入、检查、修复和消费版本。

策略程序在同一预算内有界执行，不能强开crew、扩大权限、跳过检查或修改冻结契约。
未配置策略沿用已有测量planner；不适用返回baseline；未验证候选不生效。
prepare、原生hook、READY和owned command核对指针；切换未结算、版本变化或撤回后拒绝旧计划。独立验收和取消结算不因撤回被封死。
候选统计预算、留出、恢复与撤回继续使用 `goal_evolve.py`，没有新建策略平台。

### 4. 产品与外部评测分离

正常skill/plugin由宿主负责模型、上下文、工具和原生subagent。
原外层监督器移至 `devtools/goal_loop.sh`，正常安装不复制devtools；旧 `scripts/goal_loop.sh` 返回迁移说明和rc=4，不调用客户端。
原预算、生命周期及恢复断言保留，只迁移被测路径。

真实小样本仅通过显式 `devtools/evaluate_entry.py` 使用用户已提供的客户端。
四次均沿用用户已授权的 bypassPermissions；后续开发工具默认保留宿主权限，只有显式参数才转发权限模式。
该开发工具参数改动晚于完整回归，单独保存补丁并做 `--help` 检查；不冒称其字节进入277项完整运行。
