# 视觉目标与验收覆盖修复（2026-11-14）

用户提供的圣索菲亚案例说明：严格执行自定检查，不等于完整实现用户目标。本轮修复 `goal-loop` 的原始请求、视觉判读和缺陷结算路径。原圣索菲亚项目保留为反例，建筑模型没有在本轮重建；历史工程评分也不作为开放式视觉交付能力的证明。

## 实现

- Objective 保留用户原文；按原始请求加载能力说明，视觉品质不再依赖作者先选择 `judged` 才被路由。“尽可能”等改善意图也在写 AC 前路由至已有 gradient/forge。
- 首次 `begin/enter --request-stdin` 可在没有 prompt hook 时保存原始任务；显式 `/goal-loop 目标` hook 也保留首次请求。普通对话、后续提示和 worker 正文不捕获，续跑不能覆盖原任务。读 stdin 前记录手动入口时间；未关闭的输入管道有界失败，不重起预算。
- `quality: visual AC-N views=...` 指定已承诺的质量 AC 和机位。常见构建/逼真请求缺少它时拒绝盖戳或 GO。质量 AC 必须 `judged`，且有不同字节的 good/bad 校准锚点；Objective、已有原始请求、机位和锚点字节随原事务冻结。
- 冷席比较原始目标、实际参考、校准锚点和全部实际机位，返回原始复审 JSON。控制器原样保存，既有质量判词绑定这个文件的 SHA-256；Gate 进一步核对每张图的路径/哈希、完整机位覆盖及未解决 finding。
- 顶层 `clear`/PASS 不能覆盖非空 findings、报告 FAIL/UNVERIFIABLE、失败机位或被替换的证据。质量 floor 不能借普通 UNVERIFIABLE 配额免除，中间质量水位也核对同一证据。
- 像素统计只作渲染冒烟检查。校准必须识别接近真实失败的反例；“与同一参数表一致”及“两端共享断言”不能代替外部正确性。已知核心缺陷需修复或作为部分交付保留，不能自行改称可接受盲区。
- 普通确定性维护保留原快车道；新增回归覆盖 THREE.JS import、判据分类器维护及 3D 场景模块类型修复，避免仅因提到视觉技术就强加视觉交付流程。

数据复核器只读取归档和哈希，不执行模型、浏览器、NPM、策略或验收命令。它核对实际基线接受、当前拒绝、监督过程记录、独立判读输入、原始图像、校准、失败保留、修正版接受及预算限制。语义判断来自实际冷席观察，数据复核不会把哈希本身解释成视觉真实性。

## 边界与使用

自动意图检测只覆盖常见措辞；完整目标覆盖仍需 agent 读取原始请求并复核。截图哈希证明被判读的文件身份，不能独自证明参考正确、捕获器可信或模型判断正确。捕获应针对当前实际应用/构建，保留视角与源版本信息；旧 bundle、人工合成图片和被修改的验证器不能冒充当前产物。

现有 `~/.claude/skills/goal-loop` 指向本仓库，重新开会话并调用 Skill 工具才能避免旧会话已加载的说明。原案例旧 GO 是历史记录；现有弱契约在新规则下不会再获 GO。按原修订流程补足真实参考、质量判读和改善协议后，才继续修复实际模型并获得新判读。

本轮证明的是该反例已被拒绝、合格证据有可走通的接受路径，以及相关回归边界。它不证明未来任意建筑会自动变得逼真，也没有新的综合自评分或普遍效率声明。
