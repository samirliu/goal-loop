# 固定检查入口与同批单 worker 基线

先前的失败波次、权限挂起、实际中断和迟到结算全部保留。此版本不恢复
36 项对照；只校准 W5 的同一批工作在一个 worker 和两个 worker 下的成本。

先在独立 controller-only 记录中完成 READY 和 --check 两个固定能力入口
的真实权限校准，不批准任意 Python/shell 前缀。它不计作 native worker
READY，也不混入模型样本。worker 简报包含完整任务，只要求直接 READY、
修改所属文件、调用返回的固定检查，不生成内联 shell/heredoc 自检。

同一隔离项目、同一初始字节、验收契约和最终 grader，3 对重复观测：
单 worker→crew，crew→单 worker，单 worker→crew。共 9 个全新 worker，
使用相同的未覆写宿主默认模型；未暴露的模型版本/费用保持未知。输入
是同一 auditlog 任务的重复执行，不能据此推断跨任务统计优势。

整套最多 1800 秒，包含每波准备、模型规划、启动、权限等待、协调、join、
返工和独立检查。复用项目沿用最早截止，不重新起表；预算不足则停止，
保留未完成样本，不为完成数量追加预算。每波收集实际结构化宿主终态、
独立 validate/adopt、final check、所占 worker 秒和阶段时长。

planner 用冻结契约、最终检查、输入字节和初始文件范围绑定整批条件，
允许比较不同拆分。单 worker 观测不伪造每个子任务耗时。至少 3 次近期
单 worker 和 crew 观测后才建议扩充；完整失败和未知启动仍在窗口中。
比较最便宜的已测串行基线，保留 worker 总占用的权衡；单 worker 赶不上
截止而 crew 能赶上时，可以选择唯一已测可行方案。区间是观测范围，
不声称置信区间，也不外推相对 `/goal` 的普遍优势。
