# W3/W4 接入与 W5 原生 crew 开发验证

按用户新的优先级执行；已停止的 36 项对照不重开。

材料是宿主真实 spawn/list/interrupt 回执、最早工具起点、文件字节、独立检查输出和进程写入记录。模型终报不作为成功判定。先跑 native adapter 的预算、重复/乱序回执、并发及实际工具取消，再进行模型任务。

真实任务复用已有 auditlog 中型案例及独立 grader，以减少新建评估器的风险。两个文件域共享预先固定的函数接口：T1 管 codec/CLI，T2 管 aggregation。依次比较串行委派、并行 crew、单 worker 完成全包；默认模型配置保持一致，每个 worker 使用全新上下文。前两组在同一隔离项目、同一契约和初始字节上运行。第三组回答“一个 worker 是否已经足够”，其图结构不同，不混入现有 crew planner 的同条件历史。

记录每波 dispatch→独立 final validation 的墙钟、每个 worker 的 dispatch→宿主终态总占用、first-tool-ready、协调/join/复验、失败和采用摘要。first-tool-ready 不等于第一 token 或第一份合格产物。另记录整套准备→结束时间；不把分波耗时说成完整用户请求耗时。未暴露的 tokens/费用保留 unknown。

首组是接入开发验证，一组结果不产生统计优势或通用策略晋升。planner 保留原来的每模式至少 3 次观测要求；证据不足就继续建议串行，不为得出 crew 结论降低门槛。所有失败、取消和修复前记录保留。若继续累积样本，将使用新的 trial 身份并在全部原生 worker 确认终止后才恢复初始字节。

另用真实宿主 worker 做取消注入：先观察所属工具心跳，再写 ticket 取消标记并请求宿主 interrupt，最后读取真实终态和验证停止写入。取消请求回执不得记为取消完成，不终止共享 daemon。

W7 在 W5 之后执行：实际 Agent 从原始失败/成本记录生成候选，冻结输入与 grader，配对开发/留出决定是否启用。实际运行读取归档启用指针；监测反例可以撤回。跨任务测试只证明明确测量的适用范围。示例内置候选代码不能作为“真实 Agent 产生候选”的证据。
