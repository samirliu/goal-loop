# 默认校准、资格复用与真实路由收益（2026-11-14）

本轮补上此前 [8.7 分评估](../execution-evolution-20261114/README.md) 的两个主要缺口：新实验必须先校准真实 grader；合格策略在后续完整工作流中确实改变执行，并接受原 audit/Gate。评分与全量验证另见文末记录。这里的效用证据限于本地进程执行真实仓库测试，未测量完整模型调用任务。

## 实现

- 新 v1/v2 比较缺少 good/bad 声明时，在建立状态前拒绝。校准使用原试验及总截止；过期不执行 grader 或策略，也不误记成仪器损坏。
- 新选择绑定完整资格报告的 SHA-256。后续 `run-enabled`、plan、dispatch 和原生 prepare 复核报告、冻结原料、校准输出和配对资格；损坏材料、撤回或过期选择不再授权派工。取消仍可执行。
- 旧档案与未完成事务保持可读、可恢复。旧五字段选择不会自动获得新保证；在原状态中用新留出任务重新取得资格，沿用暴露历史和顺序统计预算。同一程序重新取得资格也会使旧计划失效。
- 有真实整波收益依据的 `choice:crew` 可改变未知成本时的串行建议。文件域、依赖、容量、显式 inline、剩余截止和原终验仍生效。预算比较使用观测到的完整 trial 最大成本加策略开销，属于观测依据，不能保证所有未来任务耗时。
- 反馈直接提供真实失败输入、输出、stderr、当前资格、下一轮 alpha 和最少新留出样本数。skill 正文只增加条件入口，详细协议留在 gradient pack。
- 此前账本单次完整校验、地图消除重复读取、指纹批量规范化的改进保留。没有跨观察缓存、放宽 Gate、重置预算、全局安装或推送。

## 实际学习与消费

[固定协议](preregistration.json) 在测量前声明每阶段 6 对、最低改善 15%、trial 90 秒、总实验 900 秒、seed 141601、零重试。72 个不同测试实现位置分给开发与留出；另留 12 个不同实现位置给两个后续实例。没有按实测速度挑选留出任务。

基线使用原 planner 的未知成本串行路径；候选在同一容量内采用三个独立进程。每个 job 实际运行两项 unittest，产物 checker 要求请求 ID、执行数完全覆盖，且失败、错误、skip 均为零。整波测量包括准备、worker、协调、单元验证、join、最终验证、原收账、audit/Gate、项目归档与清理。候选没有调用模型或原生 agent。

| 范围 | 基线合计秒 | 候选合计秒 | 成本下降 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 开发 6 对 | 148.204 | 87.582 | 40.90% | 全部通过原终验 |
| 留出 6 对 | 133.986 | 92.735 | 30.79% | 全部通过原终验 |
| 后续新实例 2 对 | 30.896 | 21.610 | 30.06% | 实际消费资格，四次均通过 |

开发与留出均为 6/6 配对改善，单侧 sign p=1/64；留出使用原第一次 alpha=0.025。两阶段按 AB/BA 交替执行；后续实例顺序为基线→学习、学习→基线。后续时间包括状态复制和实际资格消费。两次后续实例只是有限的新任务观察，不能单独建立普遍统计优势。

原始材料包含 30 个完整项目：24 次配对执行、4 次后续执行、1 次正确校准与 1 次损坏产物校准。29 个正确产物通过，正常退出但错误计数的产物被拒绝；另一个无效 JSON 决策校准在启动工作流前拒绝。没有把受控 telemetry 测试、建议打印时间或重复串行基线加入效用样本。

学习实验本身实耗 **468.882 秒**，后续两次目前合计节省 **9.287 秒**，尚未回本。按这两个实例的平均节省推算，仅覆盖实验耗时至少需要约 **101 次**同类后续调用；这是假设收益持续的算术估计，不含作者研究、准备、复核、CI 或模型费用。完整研究回本、token 与账单仍未知。

## 旧归档取得新资格

[升级计划](upgrade-plan.json) 对同一个 set-safe 程序字节重新比较：20 对开发与 20 对新留出，29.066 秒完成，留出成本下降 78.78%。状态的统计评估次数从 2 增至 3，留出 alpha 从原历史继续收紧到 0.05/12；暴露集合从 52 增至 92，没有重置。它证明兼容路径和资格刷新，函数级收益不与整波路由收益合并。

## 独立重建

```sh
python3 -B docs/evals/qualified-routing-20261114/verify.py
python3 -O -B docs/evals/qualified-routing-20261114/verify.py
python3 -B docs/evals/qualified-routing-20261114/verify.py --recheck-gates
python3 -B docs/evals/qualified-routing-20261114/check_mutations.py
python3 -O -B docs/evals/qualified-routing-20261114/check_mutations.py
```

[归档](raw-study.tar.xz) 与 [校验入口](archive.json) 包含两次学习的冻结材料、真实 trial 输出、原始项目、运行源码和历史预算。独立复核器不调用实验引擎、策略或测试；它复用独立值 oracle/统计函数，从原始结果重建校准、配对资格、实际并行区间、产物覆盖、原终验和后续成本。`--recheck-gates` 只在项目副本上重新执行原 audit/Gate，不重跑试验，也不追认为原来的及时执行。

12 个篡改负例在普通与优化解释器下均被拒绝，包括重新封装的假收益/不完整留出、假校准、删除试验、替换源码/监督器、坏产物冒充通过、假并行、漏算后续成本、重置统计历史和伪造热路径汇总。

## 源码范围与后续更改

效用实验冻结了 74 份实际执行源码，[source-manifest.json](source-manifest.json) 记录当时更广的 130 份交付文件。最终回归随后发现旧 `test_incumbent` 的无关 checkpoint 负例缺少新校准声明；只补齐声明，保留“作用域、谱系或契约不匹配必须拒绝”和“不建立试验状态”的原断言。实现代码没有因此修改。

这项测试夹具修正仍改变了候选的完整源码指纹。归档结果继续属于原冻结版本，不能追认为新字节的试验。[实际范围复查](source-drift.json) 显示旧输入返回 crew，使用修正后真实源码哈希则返回 baseline；没有把旧规则默认安装到仓库。新源码、新任务形状或新平台应重新比较，平台迁移本身不由源码哈希保证。

之后还更新了两份说明，并给独立消费 CLI 增加空样本拒绝；它没有参与原测量，原后续消费由直接 Python 调用相同 workflow 完成。CLI 的普通/优化模式空样本负例通过。[最终源码清单](final-source-manifest.json) 与 [差异记录](source-verification.json) 明确区分这些变化，130 份当前有效载荷全部核对一致。

本轮增强的是当前仓库可执行、可复核的效率与学习机制。普遍模型能力、原生 `/goal` 胜率、跨平台效用、所有未来任务成本上界和完整研究回本仍无证据支持。
