# 局部策略进化实测：去重工具

本次验证的是可执行的“候选比较 → 启用 → 反例撤回 → 修复 → 新留出验证”机制。候选代码由 agent 提出，脚本按事先固定规则测量与选择。没有据此给整个 skill 打出 9 分，也没有把它当作相对原生 `/goal` 的效用对照。

| 阶段 | 开发/留出配对数 | 留出成本变化（相对同输入基线） | 结果 |
|---|---:|---:|---|
| dict 快速候选 | 6 / 6 | -86.54% | 两阶段质量不退步，启用 |
| 新嵌套列表反例 | 1 / 未花费 | 不适用 | 原始 TypeError，撤回基线 |
| 带安全回退的修复候选 | 14 / 14 | -86.71% | 新留出实例全部通过，再次启用 |

第一轮留出符号检验 p=0.015625，小于首次预算 0.025；修复轮 p≈0.000916，小于第二次预算≈0.008333。失败轮没有运行留出集，也没有清空历史。质量分数、地板和 horizon 由相同版本 grader 计算，不能靠更换标签、降低标准或删除失败试验晋升。

- [首次启用原始报告](enabled-report.json)
- [失败与撤回原始报告](withdrawn-report.json)
- [修复后再次启用原始报告](repaired-report.json)
- [撤回基线与修复产物的独立执行核对](restoration-check.json)

每份报告包含所有实际 trial 的耗时、输出哈希、grader 原始响应、退出原因、质量资格、策略与运行器哈希、运行环境及判定阈值。它们的 runner_sha256 对应本仓库的 `scripts/goal_evolve.py`。被撤回的原策略和修复版本都能从归档程序独立重跑，并与固定预期结果一致。

成本是试验工作区准备、Python 启动、工具执行和 grader 执行的实际墙钟时间；tokens 和费用没有可靠来源，记为 null。夹具生成、agent 生成候选代码以及演示的额外独立复验不在该配对时间里。该结果不表示整个 agent 任务耗时降低 86%，也不证明跨任务通用收益。统计规则依赖实例独立性等假设；输入内容哈希不等于语义独立或防泄漏隔离。

复放方法见 [完整示例](../../../examples/evolution-dedupe/README.md)。示例数据和规则现已公开，重新运行只是复放，不是新的留出证据。生产学习应保留原 state 和失败历史，并使用新的、未暴露的任务输入。
