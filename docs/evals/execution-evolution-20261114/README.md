## 实现与反例

- `goal_store.py` 每次观察完整遍历、验证提交链一次，复用本次选中的快照。没有跨调用缓存；同大小、同 mtime 的历史损坏仍会被下次 read/lookup/commit/recover 拒绝。恢复不再第二次解码全部历史。
- `goal_context.py` 移除紧邻的重复视图验证。编图仍在同一目录锁下先验证，receipt 仍在原 audit/Gate 前后验证；预算、版本绑定、恢复和终验没有替换。
- `goal_parse.sh` 让已有 Python 哈希器消费原清单并完成规范化，省去逐路径打开临时追加文件。保留外部 sort、哈希自检、Git 清单错误、shell 后备及内容读取；原指纹格式不变。
- `goal_evolve.py` 可在任何策略试跑前执行真实 grader 的 good/bad 校准；失败不花留出统计预算、不撤回既有策略。校准原料、原始输出进入冻结材料和恢复校验，消耗原总截止。示例默认启用；旧协议保持兼容，其反馈明确为 `not-declared`。
- 实验 JSON 直接返回 `feedback`，包括真实失败输入/输出、stderr、当前选择、下一轮顺序检验 alpha 和最少新样本数。历史选择已变化时提示先复核；只读命令可在恢复会话中重取反馈，不生成判词或重置统计预算。
- 最终示例复查改用显式检查。在 `python -O` 下，原版曾对注入的错误输出打印 PASS；现在拒绝。该测试使用受控 runner 输出，只证明复查机制，不能加入策略效用统计。
- `.gitignore` 排除 Python 缓存，保留原有未跟踪工作与验证材料。

旧坏 grader 反例用一个故意等待的正确基线、快速错误候选和全判通过的 grader。原引擎真实晋升了错误候选；声明好坏样本后，新引擎在策略试跑前返回 `instrument-invalid`。这是仪器负例，**不是提速样本**。
