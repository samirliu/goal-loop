## P0：结算窗口内的状态读取开销

原日志只保留断言，没有 Gate 阶段计时，不能从远程日志直接判断是哪一条检查耗尽窗口。本地先以原参数串行复现 28/76/77，八条断言通过；随后在未修改生产源码前加入最小反例：仅对读取 `^key=` 的 grep 子进程施加每次 0.12 秒固定延迟，绿色单 AC 真实收账后执行原 Gate。原版在约三秒处 rc=3，检查尚未执行；原失败、完整输出、源码身份均保留。

`gp_state_get` 每次读取单键启动 grep/tr/tail/cut 四个进程。Gate 重复读取多个键，进程启动/调度开销属于结算成本。修复只用 Bash 内建逐次读取当前 state.rec，保留 CR 清理、重复键末行优先及无换行末行。不缓存状态，不改变预算、锁、核账、指纹、检查或完成判定。

`p0-phases-before.log` / `p0-phases-after.log` 通过同一只读探针记录真实 access、非阻塞 flock、verify_views、fingerprint 和原 runtime spans。前者 rc=3；后者 rc=0 且命名检查确实运行。锁是非阻塞获取，没有锁等待；核账和 Python 指纹正文为毫秒量级。shell 入口到 access 观测包含解释器和探针启动，其余差额包含 shell 管道、解析及子进程启动，不能误称全部为哈希计算时间。阶段嵌套时间不相加。

离线定向：28/76/77 八断言，parser 81 断言，Gate entry 七项、Gate budget 三项通过。后两组保留启动延迟、核账延迟、哈希延迟、批次超时与更短继承截止负例；三秒结算与原 4.2 秒清理断言均未放宽。最终跨平台完整 CI 必须另以同一提交的实际结果确认。

## P1：可消费的执行地图

首次无账本提供原 init；首次无契约提供模板和冒烟/stamp；正常单任务从 work-plan 只取 task/files，检查计数、progress、exit 和 adversarial 均保持未知。`close_input` 是调用输入而非账本，缺必填项时 `command:null`，每项都有实际证据来源。模型只补这些必要判断，刷新后执行准确 close 命令。Gate 始终重跑验收，不信任输入计数或勾选。

已有 graph 时，地图编译 plan/begin、原生 prepare/attach/reconcile/validate/adopt/finish；缺实际身份或宿主回执时不生成命令。每个波次从原锁内记录 book_iteration，完成未收账时禁止再开波。输入、原生回执、接口、策略、产物或工具字节变化均使旧 revision 失效。context 不运行策略、不创建 worker、不写派生缓存。

context 的原目录读锁足以核对视图，移除了 ctl→锁解释器→ctl→context 的重复入口，同时允许 pending 期间返回唯一 recover 动作。原 journal/commit 增量保留精确 argv，并校验它与原 ID/intent 相符。提交前中断恢复原请求；提交后及丢确认重放原请求，不多记迭代。退出后地图转向原 audit+Gate 的 receipt，REPLAY 不能充当新鲜 GO。到期只结算，不派新工作；更短继承截止不被重建。

八项 `test_context_actions.py` 通过：空项目/无契约、正常单任务、完成未收账、真实提交点前后中断、原生生命周期地图、已声明退出、到期收账与终验、改变产物/输入/原生回执/验收证据及虚报计数。另保留原 context、预算、恢复和学习回归。测试里的原生 JSON 回执明确是机制夹具，没有实际模型或 native worker，不进入真实收益统计。
