## P0：结算窗口内的状态读取开销

原日志只保留断言，没有 Gate 阶段计时，不能从远程日志直接判断是哪一条检查耗尽窗口。本地先以原参数串行复现 28/76/77，八条断言通过；随后在未修改生产源码前加入最小反例：仅对读取 `^key=` 的 grep 子进程施加每次 0.12 秒固定延迟，绿色单 AC 真实收账后执行原 Gate。原版在约三秒处 rc=3，检查尚未执行；原失败、完整输出、源码身份均保留。

`gp_state_get` 每次读取单键启动 grep/tr/tail/cut 四个进程。Gate 重复读取多个键，进程启动/调度开销属于结算成本。修复只用 Bash 内建逐次读取当前 state.rec，保留 CR 清理、重复键末行优先及无换行末行。不缓存状态，不改变预算、锁、核账、指纹、检查或完成判定。

`p0-phases-before.log` / `p0-phases-after.log` 通过同一只读探针记录真实 access、非阻塞 flock、verify_views、fingerprint 和原 runtime spans。前者 rc=3；后者 rc=0 且命名检查确实运行。锁是非阻塞获取，没有锁等待；核账和 Python 指纹正文为毫秒量级。shell 入口到 access 观测包含解释器和探针启动，其余差额包含 shell 管道、解析及子进程启动，不能误称全部为哈希计算时间。阶段嵌套时间不相加。

离线定向：28/76/77 八断言，parser 81 断言，Gate entry 七项、Gate budget 三项通过。后两组保留启动延迟、核账延迟、哈希延迟、批次超时与更短继承截止负例；三秒结算与原 4.2 秒清理断言均未放宽。最终跨平台完整 CI 必须另以同一提交的实际结果确认。
