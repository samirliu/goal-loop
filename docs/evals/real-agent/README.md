# 真实 Agent 对照证据

正式实验协议见 [pre-reg.md](../../../examples/agent-evals/pre-reg.md)。四类任务，
各三个配对实例，每个实例比较普通执行、goal-loop 和真实宿主 Goal API，共 36 次。
开发试跑单独保留，不进入正式分母。所有 arm 继承相同父模型设置，不覆盖模型；
宿主 build 和供应商 revision 未由接口暴露，保持未知。

## 开发中发现的问题

1. 第一版观察器依赖父会话主动结算。普通执行产物通过 42 条私有检查，
   但父会话直到 1191.9 秒才结算，超过 360 秒。
   此记录保持超时，不能根据模型终报倒填成功时间。`pilot-v1.tar.gz` 保留现场。
2. 第二版加入独立进程观察完成标记和截止，宿主原生 Goal 的试跑在 241.7 秒
   完成独立验收，保存真实 create/get/complete 回执和 thread 身份。
3. 第二版 skill 的实现也通过 42 条检查，338.4 秒结算；但 DONE.json 放在工作
   目录内，使已通过的内容指纹过期，复验 NO-GO。记录保持 `protocol_compliant=false`。
   在隔离副本仅移除 DONE.json 就恢复 GO，详见 `goal-marker-regression-20261111.json`。
   第三版将 DONE/STOP 移至工作目录外，不修改 fingerprint 或验收预期。
4. 第三版 skill 在 291.7 秒完成独立验收，正确性、时限和协议均通过，
   快照复验 GO。全部现场在 `pilot-v3.tar.gz`，结果亦单列为 JSON。

主框架在冻结正式样本前通过 7 个无模型回归，包括冻结材料篡改、超时、迟到编辑、
损坏回执、真实 grader 失败和宿主身份不可替换，原始输出已保存。
正式预算统一为 600 秒，包含协议读取、规划、启动、实现和独立验收；
360 秒的开发预算和结果不追溯修改。

## 评估器校准

`grader-calibration.tar.gz` 保存四类任务已知好/坏产物及实际输出：
四个好产物通过、四个坏产物被拒绝。优化类校准最初遗漏了原任务要求的
BENCHMARK.md，评估器正确拒绝；补齐真实五次测量后重新校准，仍为开发材料。
校准不证明检查器完备。恢复类检查实际启动两个进程以及崩溃后重启，
小任务使用独立有限集合并集 oracle，不能只靠模型自报 PASS。

## 复放与结论边界

框架自检：`python3 -B examples/agent-evals/check_harness.py`。
每次正式尝试保留初始源、冻结 evaluator、完成/超时快照、补丁、原始检查输出、
时间戳和可得的原生回执。失败、环境错误、取消和协议失败保留在分母中。
模型成本不可在三组间完整观测；原生 Goal token 仅覆盖创建后的计量范围，
不等于完整调用成本。金额保持未知。

当前材料不支持“全面优于原生 /goal”或“综合评分超过 9”的结论。

首批 36 次的冻结清单为 `cohort-registration.json`。实际派发并完成 2 次：
同一小任务普通执行 330.7 秒、skill 417.5 秒，均独立正确、按时且协议合规；
skill 在这对样本中更慢，不能解释为效率优势。
独立不变量审计随后复现不合格候选污染 objective 水位，因此停止派发余下
34 个配置，先修复生产实现。全部现场和停止原因保存在 `stopped-cohort-v1.tar.gz`。
未派发配置不是失败尝试；已经完成的两次不会从历史中删除。
修复后将另冻新版本与新输入，不能把此批旧实现的结果标为新版本证据。

修复版第二批已按用户指令停止：9 次完整尝试均独立正确且按时，严格协议
通过 7 次；第 10 次 medium/skill 被实际中断并按 user-stopped 结算，
其余 26 项未派发。此次停止用于优先完成 W3/W4 宿主接入、W5 真实 crew
和 W7 真实进化，不是产品超时或失败结论。原始现场、取消回执与状态见
`stopped-cohort-v2.tar.gz` 和 `stopped-v2-*.json`；全部已完成 result 保持不变。
