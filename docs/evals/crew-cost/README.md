# Crew 成本对照

三组校准种子分别运行串行与 crew。两个启动条件使用相同的三个因数分解任务、证书检查器和总预算。决策完成后，使用此前未暴露的种子 1009 复验两种执行方式。

| 注入的启动延迟 | 校准后的选择 | 新输入串行耗时 | 新输入 crew 耗时 |
|---|---|---:|---:|
| 0.01 秒 | crew | 1.908 秒 | 0.902 秒 |
| 8 秒 | 串行 | 1.884 秒 | 8.930 秒 |

校验器验证每个因子为质数，且乘积与输入相等。两种执行方式均通过新输入检查。最后一组故障试验终止 T2，保留 T1/T3 的文件字节，只重跑 T2。原始账本包含故障记录，最终 gate 通过 3 项 AC。

[results.json](results.json) 保存全部 18 轮及失败、恢复、worker-seconds 和阶段耗时。[manifest.json](manifest.json) 固定源码、原始日志与补丁摘要。开发记录保存首次收集顺序及修正后的复测。封存运行先记录各 worker 的 READY，再观测终止，避免将等待其他结果的时间归入启动。tokens 与费用为 unknown。此对照的适用范围是本地进程和指定工作负载。
