# v4.1：让评估真正约束策略

## 改写前的四个问题

1. **顶尖从业者会额外做什么？** 先写足以推翻方案的反例，把门控正确、策略有用、跨任务迁移分开。预先固定预算、失败线与留出任务；检查错误归因、噪声和评估器漏洞，而非先扩大 crew。
2. **从什么原始材料开始？** 执行代码、逐轮工具输出、环境最终状态、实际产物 diff、检查器及其好/坏样本、每轮测量与失败记录。README、模型复盘和单次成功故事都是待证假设。此次起点为 `6c50d046d33768c74016cad824246bd7bd1e0f08` 的 `goal_ctl.sh`、`goal_gate.sh`、`scores.rec` 语义和原有 485 条断言；历史消融目录在仓库外，不能当作本次独立复验的证据。
3. **具体方法和工具？** `rg` 定位、Git 快照对照、shell 端到端反例、相邻前后测量、负例/缺失值/交错策略测试、独立 reviewer 原始轨迹复放；真实策略升级再做固定预算配对试验与串行/并行消融。实现沿用 Bash/GNU awk，不引入评估框架依赖。
4. **除了你我，还有什么能证明？** 第三方从同一提交独立重跑相同输入；不看生产者理由的校准验收器；预先封存的留出任务与真实环境状态。回归通过只支持覆盖范围内的机制结论，不能替代效用试验。

方法核对使用原始一手材料：[Anthropic, Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。其中区分轨迹与环境结果、能力与回归评估，并强调随机行为需要多个 trial。本仓库的归因修正来自可执行反例，不是该文章对本实现的背书。

## 已证实的断点与修正

| 原始输入/断点 | 旧行为 | v4.1 |
|---|---|---|
| A=0，切换 B=100 | 没算 B 进入首波的收益，靠兜底标签推荐 | B 有 +100 的一轮观测 |
| 只有 A=100 | 没有前测也推荐 A | prefer=none |
| A=10, none, 100 | 跨未知读数推算收益 | 缺失读数断链 |
| A 曾增长，重试 A 近期平台 | A 可同时 prefer/avoid | 最新窗口覆盖旧证据 |
| A 曾平台，重试首波有增益 | 旧 prune 遮蔽新证据 | 新证据清除旧 prune |
| 10,20,0,10 | 首尾相同就说平台 | 全观测范围非平坦，继续观察 |
| A=100，B=50 | 无有效 B 斜率，仍兜底推荐 B | avoid=B |
| 缺失真实末轮，存在孤立分数 | 孤立值补出 eval-gap | 必须来自最新相邻账本轮次 |
| 声明 sd/var，但分数账本无波动量 | tolerance 单独决定推荐 | noise-unverified，暂停推荐 |

一个 `goal_strategy.awk` 同时提供显示和路由使用的 pick，避免两份计算漂移；gate 完成权保持不变。增益归整波，不将联合修改伪装成 worker 独立贡献。指标被声明有噪声时，暂停建议并补测，比假装已有显著性更诚实。

## “自我进化”的证据门槛

当前任务内的局部策略调整可以自主继续。可复用策略/skill 升级走现有 proposals：失败原始轨迹 → 可复现反例 → 最小政策差异 → 留出任务配对试验 → 保留或回退。生成者不得在评估时改评分器或成功定义。

真实效用试验尚未执行。预注册模板规定固定同一模型、起始状态、验收器和总预算，多次配对比较旧/新策略及串行/并行消融。至少报告：

- 交付率：通过独立验收的任务数 / 全部尝试。
- 每次有效交付成本：全部尝试的总成本 / 成功交付数；零成功为未定义。
- 交付时间分布：median/p90；失败按预算删失记录，不从样本中丢弃。
- 回归/代理指标失真：地板检查、校准负例、留出任务是否退化。

tokens、费用或真实计时缺失时写 unknown；波数不能代替成本。当前窗口比较不证明因果，策略标签的语义由控制器提供，且冻结脚本不覆盖所有传递依赖。这些是明确的证据边界，不得在最终报告中升级为“已经全面超越 /goal”。
