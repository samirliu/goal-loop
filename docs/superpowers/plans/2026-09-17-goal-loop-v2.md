## T7 判决书实验（详细步骤）

同一提示词、同一项目目录基线，v2.0 vs /goal 各跑一次：

1. 新建干净对照目录两个（或同目录先后跑，产物分别归档）；提示词固定：
   "使用 THREEJS 创建最逼真的波音 747 - 使用你的视觉能力创建一个自我验证系统"
2. Run A：/goal 跑到 Goal marked complete（上轮已有基线产物在
   ~/b747-threejs，可复用为 Run-A 参照，不必重跑）
3. Run B：/goal-loop 跑 v2.0——注意：747 是单一耦合交付物，crew 选举可能
   合法拒绝（几何/贴图接口强耦合），退串行单任务。因此本实验测的是 v2.0 的
   驱动+门控身份与协议税，**不测 crew 并行**；crew 并行需另选多模块任务
   （量化系统/portal）单独立项。观察点：
   - crew 是否触发（拆解是否产出 ≥2 可接口化的模块域）
   - 协议时间占比（契约+join+gate 耗时 / 总耗时，目标 <10%）
   - 确定性断言是否引用真规格（Goodhart 哨兵检查）
   - 终验冷席一轮过线与否
4. 盲评：两版相机系统不同（v2.0=verify/shot.sh 预设，/goal=src/main.js 内置
   机位），先用统一机位规格（frontq/side/engine/tail 的位置+朝向数值）对两版
   分别截图，再混淆顺序交独立视觉席打分（rubric 同 b747）
5. 判定标准：盲评分差 ≥0.5 或持平且协议时间占比 <10% → v2.0 crew 身份成立；
   /goal 仍显著优 → 两轴法则按新证据修正。
6. 记账：结果写入本文件 + 记忆
